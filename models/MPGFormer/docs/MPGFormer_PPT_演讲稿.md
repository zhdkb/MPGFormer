# MPGFormer 汇报 PPT 演讲稿

> 对应文件：`models/MPGFormer/docs/汇报.pptx`  
> 建议时长：15-20 分钟  
> 讲述主线：先说明云工作负载预测为什么难，再引出“预测证据会随窗口状态变化”这一核心动机，最后说明 MPGFormer 如何通过时间证据、原型证据、图证据和漂移感知路由完成预测。

## 第 1 页：标题页

各位老师、同学好，我今天汇报的题目是 MPGFormer，全称是 Drift-Aware Multi-scale Prototype-Graph Transformer for Cloud Workload Forecasting。

这项工作的核心观点可以先用一句话概括：云工作负载预测并不是简单地从过去预测未来，而是要判断当前这个时间窗口到底应该相信哪一种预测证据。

在真实云平台中，同一条工作负载序列并不会一直保持同一种模式。它有时表现为稳定周期，有时突然出现高负载尖峰，有时会和其他实例一起同步波动，有时又会偏离历史典型模式。也就是说，模型不能固定地只相信历史时间依赖，也不能固定地只相信周期或图关系。MPGFormer 想解决的问题，就是让模型根据当前窗口状态，自适应选择时间证据、典型形态证据和跨序列证据。

下面我会按照背景、研究动机、核心挑战、方法实现和实验设计这几部分展开。

## 第 2 页：研究背景

这一页是汇报结构的第一部分：研究背景。

云工作负载预测是云计算资源管理中的一个基础问题。它看起来像普通时间序列预测，但实际上和云平台调度、资源利用率、服务质量保障都有直接关系。

接下来我会先说明为什么云平台需要预测，然后再解释真实云工作负载和普通时间序列的不同之处。

## 第 3 页：云平台中的工作负载预测

在云平台中，工作负载预测主要服务于几个典型场景。

第一是自动扩缩容。如果我们能提前预测 CPU、QPS 或内存使用量即将上升，系统就可以提前扩容，避免负载已经上来之后才被动响应。反过来，如果预测到负载会下降，也可以及时释放资源，减少浪费。

第二是资源预留和容量规划。云平台中既有在线服务，也有批处理任务，还有维护任务和调度迁移。如果没有对未来负载的判断，不同任务之间就容易互相挤占资源。

第三是 SLA 和成本之间的平衡。资源给少了，服务性能会下降；资源给多了，又会造成长期过度配置。所以更准确的预测可以帮助平台在服务质量和成本之间取得更好的平衡。

但是，真实 workload 的复杂性来自很多因素。用户行为会带来日周期和活动流量，系统行为会带来调度、迁移、维护和限流，平台耦合还会导致多个实例因为共享上游流量或资源竞争而一起波动。

这里最重要的观察是：即使服务、机器和应用都不是新的，同一个 workload 在正常运行过程中也会经历不同状态。不同状态下，最可靠的预测证据并不相同。因此，模型不仅要学习历史到未来的映射，还要理解当前窗口应该相信哪类信息。

## 第 4 页：研究动机

这一页是整个工作的核心动机。

我们把同一条 workload 在不同时间窗口中的状态分成四类直观情况。

第一类是稳定周期窗口。这类窗口里，历史节律比较清晰，比如每天或每几个小时重复出现类似的峰谷。此时模型更应该相信时间记忆和多尺度周期形态。

第二类是突发高负载窗口。这种情况下，最近几个时间点突然升高，短期局部变化比很长时间以前的依赖更关键。如果模型只看长期平均，很容易把尖峰抹平。

第三类是协同波动窗口。比如多个相似实例同时受到同一批请求、同一个调度事件或同类业务行为影响，它们会一起上升或下降。这时候，仅看当前实例自身历史是不够的，其他相似窗口可以提供外部证据。

第四类是漂移或非典型窗口。这里的重点不是突然尖峰，而是当前窗口整体的均值、方差或形态已经偏离过去的典型模式。如果仍然盲目按照旧周期外推，就会把新的状态误认为历史噪声。

所以这项工作的动机不是再提出一个更复杂的 Transformer，而是把云工作负载预测理解为一个证据选择问题：当前窗口到底应该主要相信自身历史、典型原型，还是其他相似实例？

## 第 5 页：核心挑战

基于刚才的观察，我们可以把问题进一步总结成一个核心挑战：固定证据假设不适合云负载。

也就是说，云工作负载难的地方不只是曲线有噪声，而是同一个服务在不同窗口中会切换运行状态，导致模型可以依赖的预测证据也会变化。

具体来看，第一是状态非平稳。同一条 workload 的局部均值、方差和波动幅度会随时间改变。在一个窗口里看起来异常的高负载，在另一个窗口里可能已经变成新的正常水平。

第二是突发稀疏但代价高。尖峰通常只持续少数时间点，在训练样本中占比不高，但它会显著影响 MSE，也会直接影响扩缩容和 SLA 风险。

第三是跨序列关系会临时出现。多个实例可能因为同一个上游流量、同一批调度任务或资源竞争而同步变化，但这种关系不是固定拓扑，不能假设它一直存在。

第四是历史模式会失效。当当前窗口偏离过去的典型形态时，继续按照旧周期或旧原型外推，就会把漂移误认为周期，把状态变化误认为噪声。

因此，稳定周期、突发、协同波动和漂移并不是简单的噪声类型，而是会改变“哪种证据最可信”的运行状态。这也正是 MPGFormer 要建模的核心。

## 第 6 页：研究方法

接下来进入方法部分。

MPGFormer 的设计思路是：既然不同窗口需要不同证据，那么模型就不应该只依赖单一分支，而是应该先提取多种证据，再根据当前窗口状态决定如何融合。

后面几页我会先讲整体框架，再分别解释输入构造、时间证据分支、多尺度原型分支、动态图分支、漂移感知路由器以及最终 decoder 输出。

## 第 7 页：MPGFormer 总体框架

这一页是 MPGFormer 的总体框架。

模型的输入窗口长度是 72，其中前 48 个时间点作为历史，后 24 个时间点作为预测目标。这里的 48 history 用来编码当前窗口的历史状态，24 future 是模型最终要预测的未来值。

输入进入模型后，首先进行预处理。Target RevIN 只对目标通道做窗口级归一化，目的是减少局部尺度变化带来的干扰。然后通过线性映射、位置编码和静态上下文融合，把原始输入变成高维历史表示。

接着模型并行提取三类证据。

第一类是时间证据 c_time，它回答的问题是：从目标序列自己的历史中，哪些长短期变化对未来最有用。

第二类是原型证据 c_proto，它回答的问题是：当前窗口像不像过去学习到的某种典型负载形态。

第三类是图证据 c_graph，它回答的问题是：当前 batch 里有没有其他相似窗口可以为当前预测提供参考。

最后，漂移感知路由器根据当前窗口状态为三类证据分配权重，得到融合上下文 c_fused，再交给 decoder 生成未来 24 步预测。

这里需要强调的是，MPGFormer 不是把所有模块简单拼接，而是先提取三种不同来源的证据，再通过 router 动态决定当前窗口更应该相信谁。

## 第 8 页：输入与窗口构造

这一页说明模型到底看到了什么。

原始数据统一组织成三维形式 data ∈ R^{N×T×F}。其中 N 表示 workload 序列数量，T 表示时间长度，F 表示每个时间点的特征数。

在训练时，我们从每条序列中滑动切出长度为 72 的样本窗口。前 48 个点是 encoder history，后 24 个点是预测目标。为了防止信息泄露，未来 24 个点中的 target 通道会被 mask 掉，模型不能直接看到未来真实值。

进入模型后有两个关键张量。

第一个是 H_s ∈ R^{B×48×128}，它是每个历史时间点的高维隐藏表示。可以理解为：原来的每个时间点只有几个原始特征，现在被映射成 128 维，用来表达更丰富的上下文信息。

第二个是 target_history ∈ R^{B×48}，它只包含目标通道过去 48 个点的真实历史值。它的作用不是直接做高维编码，而是用来计算窗口均值、方差、漂移特征，以及进行原型匹配和图构建。

另外 decoder input 的长度是 36，由最后 12 个历史点和未来 24 个位置组成。未来 24 个位置一开始没有真实 target，所以会由原型分支生成 future_padding 作为初始填充值。

## 第 9 页：时间证据分支

这一页讲时间证据分支，也就是模型如何从当前 workload 自己的历史中提取信息。

这个分支同时用到 H_s 和 target_history。H_s 是高维序列表示，是 attention 和短期编码器真正处理的对象；target_history 是目标通道数值，用来告诉模型当前窗口的均值、方差和波动状态。

首先是 Non-stationary Attention。普通 attention 会计算不同时间点之间的相关性，但它通常默认不同窗口使用相似的注意力尺度。MPGFormer 这里根据 target_history 的均值 μ 和标准差 σ 生成 τ 和 δ，用它们调节 attention logits：

logits = τ·QKᵀ/√d + δ。

这样做的直观含义是：不同窗口的波动程度不同，attention 的集中程度和偏置也应该随窗口状态调整。

然后是 Moving-Average Decomposition。它把当前隐藏序列分成 trend 和 seasonal 两部分。trend 是 moving average 得到的低频平滑趋势，seasonal = x - trend，表示高频残差、局部波动和周期扰动。

最后是 Short-term Temporal Encoder。这里用 Conv(k=3) 捕捉非常短的局部尖峰，用 Conv(k=5) 捕捉稍宽一点的短期波动，再用 BiGRU 建模相邻时间步之间的顺序变化。最后将局部卷积特征和循环特征拼接，再映射回 128 维。

时间分支最终输出 c_time ∈ R^{B×128}。它可以理解为对当前窗口自身历史的总结：这个窗口自己的时间依赖、趋势和短期变化，对未来预测有什么帮助。

## 第 10 页：多尺度原型分支

这一页讲多尺度原型分支。

原型分支的输入是 target_history，也就是目标通道过去 48 个点。它的核心想法是：云工作负载中有很多反复出现的典型形态，比如周期上升、低谷恢复、平台高负载、突发后回落等。我们希望模型能够显式记住这些形态，并在当前窗口中检索相似模式。

具体地，模型用四个尺度切分 48 点历史。

p=6 时，48 个点会被分成 8 个短 patch，用来捕捉局部片段形态。

p=12 时，会得到 4 个 patch，用来捕捉中短期变化。

p=24 时，会得到 2 个 patch，用来捕捉半窗口级别的形态。

p=48 时，整个历史窗口就是一个 patch，用来表示整体形状。

需要注意的是，p=6 拆出的 8 个 patch 并不是分别去匹配 prototype。它们会先经过 Linear 映射成 128 维，再对 8 个 token 求平均，得到一个 p=6 的 scale token。同时，模型还会对每个 patch 做 FFT，得到频域幅值，再映射成频域 token。时域 token 和频域 token 合起来，表示这一尺度下的形态信息。

之后，每个尺度都有 K 个可学习 prototype。scale token 会和同尺度的 K 个 prototype 做点积相似度，并通过 softmax 得到匹配权重。每个尺度先得到一个原型表示，再由 scale weights 把四个尺度聚合成 c_proto。

最终，原型分支输出两个东西：c_proto ∈ R^{B×128}，表示典型形态证据；future_padding ∈ R^{B×24}，用于给 decoder 的未来 target 位置提供一个更合理的初始轨迹。

## 第 11 页：动态图分支

这一页讲动态图分支。

图分支的基本思想是：当前窗口不一定只能靠自己的历史预测。如果 batch 中有其他窗口和它最近的行为很相似，那么这些窗口也可以提供外部证据。

这里每个 batch 中的一个窗口就是一个图节点。比如 batch size 是 64，那么当前动态图就有 64 个节点。这个图不是预先固定的，而是在每个 batch 内根据相似度动态构建。

模型构建两类图。

第一类是 workload graph，它基于 target_history 的 cosine similarity。也就是说，如果两个窗口过去 48 个目标值的形状相似，它们之间就更可能连边。

第二类是 context graph，它优先使用 static context。如果没有静态上下文，就使用窗口统计特征，比如均值、方差、差分变化等状态信息。

得到图之后，模型用 GCN 做消息传递。直观上就是：当前节点保留自己的信息，同时聚合 top-k 相似邻居的信息。因此可以理解为 A_new = self + neighbors。

两个图视图分别得到表示后，还通过 contrastive loss 进行约束，让同一个窗口在 workload graph 和 context graph 下的表示保持一致。

最终输出 c_graph ∈ R^{B×128}，表示跨序列协同证据。举个例子，如果当前实例最近突然升高，而 batch 中多个形态相似的实例也同步升高，那么图分支会把这种协同升高作为预测依据。

## 第 12 页：漂移感知路由与 Decoder

这一页是 MPGFormer 从多证据到最终预测的关键。

Router 的输入包括三类上下文：c_time、c_graph 和 c_proto。除此之外，它还会输入漂移特征，比如 z_last、mean(|Δ|)、std，以及 prototype entropy。

其中 prototype entropy 很重要。如果当前窗口和多个 prototype 的匹配都比较平均，说明模型不确定它到底属于哪种典型形态，此时就不应该过度相信原型证据。

Router MLP 输出三个权重：w_time、w_graph 和 w_proto。经过 softmax 后，这三个权重加起来等于 1。融合公式是：

c_fused = w_time c_time + w_graph c_graph + w_proto c_proto。

也就是说，对于稳定周期窗口，时间证据和原型证据可能更重要；对于协同波动窗口，图证据可能更重要；对于原型不确定的窗口，router 会降低对原型的盲目信任。

然后进入 decoder。decoder input 长度是 36，包含最后 12 个历史点和未来 24 个位置。未来 24 个 target 位置先由 prototype 分支的 future_padding 填入，再由 Transformer decoder 根据 encoder memory 和 c_fused 进行修正。

最终预测头输出未来 24 步点预测，同时还输出 q10、q50、q90 分位数区间、上下界，以及 router weights、drift score、prototype weights 和 graph adjacency 等可解释信息。

## 第 13 页：完整模型结构图

这一页是完整架构图，主要用于把前面讲的模块连接起来。

从左到右看，左侧是输入准备和预处理，包括原始数据、滑动窗口、target 归一化和历史表示生成。

中间是多证据提取部分，包括时间证据分支、多尺度原型分支和动态图分支。它们分别从自身历史、典型形态和相似窗口中提取信息。

右侧是漂移感知融合、decoder 和最终输出。Router 根据当前窗口状态决定三类证据的权重，decoder 再基于融合上下文生成未来 24 步预测。

这张图可以回答一个核心问题：MPGFormer 不是把所有信息混在一起，而是把“证据来源”拆开建模，再让模型自己学习当前窗口应该相信哪一路。

## 第 14 页：实验设计

接下来进入实验部分。

实验设计主要想验证 MPGFormer 是否真正解决了前面提到的挑战。也就是说，我们不仅要看整体 MSE、MAE、SMAPE 是否更好，还要关注模型在突发、漂移、协同波动这些不同窗口状态下是否更稳定。

所以实验部分的重点不是单纯堆指标，而是要验证：多证据分支是否都有贡献，漂移感知路由是否真的能根据窗口状态改变证据权重。

## 第 15 页：实验设置与评价口径

这一页说明实验数据和评价方式。

所有数据集都被统一整理成 [num_series, num_periods, num_features] 的三维格式。这样不同模型可以在统一输入格式下训练和测试。数据集包括 ECW、Azure VM、Google v1、Materna workload 等云工作负载场景。

窗口设置统一为 48 history + 24 future，这样可以保证模型之间的比较更加公平。

对比模型包括 DynEformer、Informer、Autoformer、Deep Transformer、MQRNN、Fremer、PDF 等。评价指标统一使用 MSE、MAE 和 SMAPE，并且指标都在反归一化后的 target 原始尺度上计算，避免不同模型因为尺度处理方式不同导致结果不可比。

这里可以设置四个实验问题。

RQ1 是整体预测性能是否优于主要 baseline。

RQ2 是在突发、漂移和协同波动窗口中是否更加稳定。

RQ3 是消融实验，也就是去掉 prototype、graph 或 router 后性能会发生什么变化。

RQ4 是解释性分析，也就是 router weights 是否能反映不同窗口中的证据选择逻辑。

## 第 16 页：总结

最后总结一下。

MPGFormer 的核心思想是：把云工作负载预测从“固定证据源的时间外推”转化为“漂移感知的动态证据选择”。

方法上，它包含四个关键部分。

第一是时间证据，通过非平稳 attention、移动平均分解和短期编码器，建模自身历史中的长短期变化。

第二是原型证据，通过多尺度时频 prototype memory，显式检索典型 workload 形态，并提供 prototype uncertainty。

第三是图证据，通过 batch-wise 动态图和对比约束，从相似窗口中获取跨序列协同信息。

第四是融合机制，通过漂移感知 router，根据当前窗口状态自适应选择证据来源。

所以，MPGFormer 不是只提出一个更复杂的 Transformer，而是围绕云工作负载状态切换这一现象，显式建模“什么时候相信谁”。最终模型不仅输出未来 24 步预测，也输出路由权重、漂移分数、原型匹配权重和图关系，使预测过程更加可解释。

## 可能的答辩补充话术

如果老师问为什么不是直接拼接三类证据，可以回答：

直接拼接默认三类证据在所有窗口中都同等有用，但云工作负载的关键问题是证据可信度会随状态变化。Router 的作用就是让模型在不同窗口中动态改变证据权重，例如稳定窗口更依赖时间和原型，协同波动窗口更依赖图证据，原型不确定时降低对 prototype 的依赖。

如果老师问 prototype memory 是怎么来的，可以回答：

prototype memory 是模型内部的可学习参数，不是每个 batch 临时生成的。训练开始时随机初始化，之后通过反向传播更新。每个尺度都有一组原型，模型通过当前 scale token 与 prototype 的相似度进行检索。

如果老师问 c_time、c_proto、c_graph 的区别，可以回答：

c_time 来自当前 workload 自己的历史，强调时间依赖和短期变化；c_proto 来自可学习原型库，强调典型形态匹配；c_graph 来自 batch 内相似窗口，强调跨序列协同变化。三者代表不同证据来源，最后由 router 动态融合。

如果老师问为什么 decoder 要用 36 长度，可以回答：

decoder input 由最后 12 个历史点和未来 24 个位置组成。最后 12 个历史点相当于给 decoder 一个已知上下文起点，未来 24 个位置是要逐步生成的预测区域。未来 target 不能用真实值，所以先用 prototype 分支生成的 future_padding 初始化，再由 decoder 结合 encoder memory 和融合上下文进行修正。
